# D2MOO -> IDA IDC scripts  (process dump)
Generated by tools/gen_ida_idc.ps1 from D2MOO .def files.
Target: IDA loaded from a Diablo 2 process dump (.dmp / full memory image).
## Strategy
In a process dump, all DLLs are mapped at their runtime addresses.
GetEntryPoint() does not work (no individual binary context).
Instead, each IDC parses the PE export table directly from the dump memory:
    idx      = ordinal - ordBase            (ordBase read from export dir)
    rva      = Dword(addrFuncsArray + idx*4)
    addr     = dllBase + rva
    set_name(addr, "FunctionName", 0x880)
No per-function addresses are hardcoded.  Only the DLL base per script.

## How to apply in IDA (process dump)
1. Open the process dump in IDA (File > Open as .dmp or raw binary)
2. File > Script file...  (Alt+F7)
3. Select the .idc for the DLL to rename
4. Check the Output window:
   - "renamed > 0" = success
   - "renamed == 0 / ERROR" = wrong dllBase, see below
## If renamed == 0 or ERROR
The dllBase variable in the IDC does not match where the DLL actually
loaded in the dump.  Fix:
  a) In IDA: Edit > Segments (or View > Open subviews > Segments)
  b) Find the segment for the DLL (look for the name or address range)
  c) Open the .idc file, change the dllBase line
  d) Run again
## D2Common_extra.idc
Covers ~10 internal functions not in the export table.
They are patched via RVA in extraPatchActions[] in D2Common.patch.cpp.
Uses the same dllBase = 0x6FD40000.
## Regenerating
    powershell -ExecutionPolicy Bypass -File tools\gen_ida_idc.ps1
    # Specific DLLs only:
    powershell -ExecutionPolicy Bypass -File tools\gen_ida_idc.ps1 -Dlls D2Common,D2Game
## IDA 6.x compatibility
Replace  set_name(a,n,0x880)  with  MakeNameEx(a,n,0x800)
